SAP2000 Automation and AI-Assisted Structural Analysis

I've been writing Python for structural engineering work for more than a decade, well before "AI tools" became a marketing category. What I build is practical: tools that reduce the mechanical overhead of structural analysis so more of the work hours go toward engineering judgment and less toward copy-paste and reformatting. The result is faster turnaround on complex analysis work without cutting corners on the engineering behind it.

sap-composer: Building SAP2000 Models from Structured Descriptions

SAP2000 is the standard tool for general structural finite element analysis, and it's powerful, but building a model from scratch is slow. I built sap-composer to generate SAP2000 .s2k input files from structured descriptions, round-trip them back into SAP2000, and produce documented, traceable model files. The practical result: a structural model that would take hours to set up manually can be ready to run in a fraction of the time, with inputs that are legible and reviewable by anyone with access to SAP2000.

This is especially useful for independent verification work, where I'm building a model to cross-check someone else's analysis rather than producing the primary design. It lets me run that check at a price and turnaround that makes sense for the scope, rather than billing for model-building time that shouldn't be the client's problem.

Independent SAP2000 Cross-Checks

One of the most useful things I do is independent structural verification: you have a design, an existing analysis, or a pre-engineered product, and you need an independent model to confirm the numbers hold. I've caught missing seismic analyses, incorrect response modification factors for cantilever column systems, and load-path errors that weren't apparent from reviewing the original output alone. Those aren't hypothetical scenarios; they're the actual findings from real peer review work.

The value isn't just error-catching. It's a documented, independent analysis that a client, an owner, or a building department can rely on as a second opinion with a PE seal behind it.

Python Automation Across the Practice

The same philosophy extends to other tools I use regularly. I built a custom input composer and output parser for LPILE, the lateral pile and drilled shaft analysis software, to handle parametric runs without manual re-entry. I built the ballast_calc library for rooftop PV ballast design, with a pluggable backend that handles both code-tabulated GCp coefficients and proprietary wind-tunnel datasets. Calculation engines for AISI S100 cold-formed steel and AASHTO LRFD buried pipe design follow the same pattern: transparent, step-by-step, engineer-reviewable output that a second engineer can follow without needing to trust a black box.

I also have a DXF drafting automation tool currently in development for generating scaled structural details and multi-sheet drawing sets directly from calculation output.

AI Assistance in Context

Large language models assist my practice in two concrete ways. First, as a model-building interface: describing a structure in structured natural language to generate a first-cut SAP2000 input file is faster than clicking through menus, and the resulting file is fully editable and auditable. Second, as a drafting tool: AI can assemble a calculation narrative or summary memo quickly, which I then review, correct, and verify against the actual engineering output before sealing.

The engineering judgment stays human throughout. I sign and stamp every deliverable, which means I've verified every number in it. AI-generated content that I haven't reviewed isn't part of a Taut Engineering deliverable. The value of AI assistance is speed on the assembly side of engineering work, not a substitute for the analysis side.
